## 二、逐项说明

### 2.1 og:image 分享卡（要求 1）

**为什么自己画而不用 ImageGen**：ImageGen 输出固定 1536×1024（3:2）且右下角带
「AI生成 WORKBUDDY」水印，裁到 1200×630（1.91:1）会切掉大量画面；分享卡上的中文标题
必须清晰可控。故改用 PIL 精确排版（`_gen_og.py`）。

**设计**：品牌主张「小乖乖，不是要你**听话**」（「听话」用强调色）+ 副标 +
域名 + 三个卖点（60 篇原创 / 20 个工具 / 纯本地运行）；右上角「乖」字淡水印作底纹。

**产物**：`_covers_out/og-brand.png` → R2 `xiaoguaiguai-media/covers/og-brand.png`
→ `https://xiaoguaiguai.cn/media/covers/og-brand.png`（实测 200 + `image/png`）。

**内页按语境取图**（避免全站一张卡）：

| 页面 | 分享图 |
|---|---|
| 首页 / 合规页 / 404 | `covers/og-brand.png`（品牌卡） |
| 文章页 | 该文所属分类配图，如 `covers/yuer-content.webp` |
| 分类页 | 该分类配图，如 `covers/qinmi-content.webp` |
| 工具页 | 该分类工具配图，如 `covers/nvxing-tool.webp` |
| 全部内容页 / 工具列表页 | `yuer-content.webp` / `yuer-tool.webp` |

同步补 `<meta property="og:image:width|height|alt">` 与 `twitter:image`。

### 2.2 末组 4 条（要求 2）

**根因**：末组「两性亲密成长」跨满整行（`grid-column: 1 / -1`）、内部再分两列。
3 条会排成「2 + 1」——第二行右半格空着，视觉上像缺了一块。

**落地**：`HOME_PER_CAT = { qinmi: 4 }`，其余 4 组仍取 3。首页索引总数 15 → **16 条**。

### 2.3 术语统一（要求 3）

用户点名两处（首页区块标题 + 导航栏），但站内其它位置（页脚、面包屑、工具列表页标题、
工具页返回链接、合规页正文、CMS 配置、CI 提示语）也写「小工具」。只改两处会造成
「导航叫实用工具、正文叫小工具」的新不一致，故**全站统一**：

| 位置 | 改动 |
|---|---|
| `build.mjs` | 16 处（导航、页脚、面包屑 ×2、工具列表页 h1 与 title、返回链接、配套工具徽标、meta desc） |
| `pages/*.md` × 5 | 15 处（关于/联系/免责/隐私/条款正文与标题） |
| `tools/tools.json` | 1 处（`_readme` 说明） |
| `admin/config.yml` | 1 处（注释） |
| `.github/workflows/deploy.yml` | 2 处（注释 + `::error::` 文案） |

**保留不改**：`README.md` 与记忆文件里描述**历史变更**的两行（「小工具由 10 个扩到 20 个」
「补其余 4 个分类的小工具」）—— 那是当时的事实记录，改了反而失真。

### 2.4 品牌区移除（要求 4）

**移除内容**：`section.brand-hero`（主张 + 副标 + 双入口 + 3 项信任标记）+ 其全部 CSS
（含 860px / 560px 两处响应式规则）。

**关键取舍 —— 首页 h1 不能一起消失**：品牌区的 `<h1 class="slogan">` 曾是首页唯一的 h1。
直接删掉会让首页没有主标题，对 SEO 与无障碍都有损。故改为：

```html
<h1 class="sr-only">小乖乖，不是要你听话 ｜ 家庭与成长实用内容站</h1>
```

`.sr-only` 是标准 clip 隐藏方案（1×1px），屏幕阅读器与爬虫可读，视觉不可见。

**焦点区升为首页第一块**：`.hero-pick` 的 `margin-top` 由 26px 调到 28px，补上原品牌区
留下的呼吸空间。

**实测首屏占用**：内容区「最新内容」起始位于 **403px**（视口 900px）—— 首屏内即可看到
内容区，这正是用户诉求的核心。

### 2.5 首页工具卡 12 个（要求 5）

**踩到的坑（关键）**：`tools.json` 是按分类顺序排列的（婴幼儿 4 → 教育 4 → 女性 4 →
家庭 4 → 亲密 4）。若直接 `tools.slice(0, 12)`，只会拿到前 3 个分类，
**「家庭关系」「两性亲密成长」一个都进不来**。

**正解**：按分类轮流取（round-robin），每轮从 5 个分类各取 1 个，取满 12 个为止。
结果：前 2 轮各 5 个 = 10 个，第 3 轮再取 2 个 → 5 个分类全部有代表。

## 四、本轮踩到的坑（复用价值高）

### 4.1 `isVisible()` 对 `sr-only` 元素返回 `true`

`sr-only` 用 `clip` 方案隐藏（`position:absolute; width:1px; height:1px; overflow:hidden`），
元素**有盒子、未 display:none**，因此 Playwright 的 `isVisible()` 判为可见 ——
用它验「视觉隐藏」必然假失败。

**正确判据**：读 `getBoundingClientRect()`，`w <= 1 && h <= 1`。
（同源坑：`offsetWidth` 对这类元素返回 0，与 `rect.width` 的 1 不一致，以 rect 为准。）

### 4.2 首屏「第一个可见区块」的判据要设高度阈值

`main` 的第一个子元素正是那个 1px 的 `sr-only` h1。用 `height > 0` 过滤会把它当成首屏区块，
断言「首块 = 焦点区」必然失败。**阈值取 8px** 可稳定排除隐藏元素与装饰块。

### 4.3 不能用 slug 前缀反推工具分类

e2e 里想验「首页 12 个工具覆盖 5 个分类」，起初用 `href.split("/")[2].split("-")[0]` 当分类前缀，
结果算出 **7 个「分类」**——因为最早的两个工具 slug 是 `baby-age-calculator`、
`complementary-food-guide`，**不带分类前缀**。

**正解**：唯一可靠来源是 `/tools.json` 的 `category` 字段，脚本内 `fetch` 一次建映射。

### 4.4 `wrangler` 不在 PATH

`npx wrangler@4 ...` 报「不是内部或外部命令」。工作区已装 wrangler 4.147.0，直接用：
```bash
node /c/Users/dynabook/.workbuddy/binaries/node/workspace/node_modules/wrangler/bin/wrangler.js \
  r2 object put <bucket>/<key> --file=<path> --content-type=image/png --remote
```
`--remote` 不能省（否则只写本地模拟桶，线上取不到）。

### 4.5 Playwright 需显式 `NODE_PATH`

`node _trash_e2e.cjs` 报 `Cannot find module 'playwright'`。工作区已装，跑验收脚本时加：
```bash
NODE_PATH=/c/Users/dynabook/.workbuddy/binaries/node/workspace/node_modules node _trash_e2e.cjs
```
