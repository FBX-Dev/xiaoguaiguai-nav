## 二、新增 8 个小工具

全部为**本站自研、纯前端、零外链、无数据上报**；数据只存在访客浏览器 `localStorage`，不上传任何服务器。

| 分类 | 图标 | 工具 | 路径 | 做什么 |

| 🌷 女性成长 | 🗂️ | 四象限待办分类器 | `/tools/nvxing-quadrant-todo/` | 按「有无时间要求」×「是否必须我做」分四格，并给出参考处理顺序 |

| 🏠 家庭关系 | 📊 | 家庭开支分配参考 | `/tools/jiating-budget-planner/` | 输入月收入按分类框架估算金额与占比，给出储蓄率与结构提示 |

**设计取向（与本站调性一致）**：工具一律**不做评价、不给分数、不制造焦虑**。例如情绪记录本明确写「不做评估、不用打卡」；阅读打卡本写「不设任务指标」；家务表只输出「耗时与占比参考」而非「谁做少了」。

两个含心理/安全话题的工具（情绪记录本、句式转换器）均内置了「需要专业帮助时找谁」的提示，不越界做诊断或咨询。

## 四、CI 增加逐分类硬校验

`.github/workflows/deploy.yml` 的 Verify 步骤新增了一段循环，**逐分类**校验文章与小工具配额，不达标直接 fail，坏内容不会发到线上：

```yaml
# 硬指标：每个分类文章 ≥4 篇、小工具 ≥2 个
for cat in "🧸 婴幼儿养育" "📖 儿童教育" "🌷 女性成长" "🏠 家庭关系" "💞 两性亲密成长"; do
  PC=$(node -e "console.log(require('./_dist/posts.json').posts.filter(p=>p.category==='$cat').length)")
  TC=$(node -e "console.log(require('./_dist/tools.json').tools.filter(t=>t.category==='$cat').length)")
  echo "  $cat → 文章 $PC / 工具 $TC"
  if [ "$PC" -lt 4 ]; then echo "::error::$cat 文章不足 4 篇（实际 $PC）"; exit 1; fi
  if [ "$TC" -lt 2 ]; then echo "::error::$cat 小工具不足 2 个（实际 $TC）"; exit 1; fi
done
```

本地模拟该循环：5 分类均「文章 8 / 工具 2」✅

## 六、过程中修掉的两个问题

### 6.1 验收脚本的「假差异」（推送前拦截）

推送脚本初版的 `--dry` 只判断「远端有没有这个文件」，不看内容，于是把 47 个**字节完全一致**的文件
全报成 `UPDATE`。改为**本地计算 git blob SHA** 与远端 tree 比对后，真实差异只有：

```
内容比对：一致(跳过) 44 / 变更 3 / 新增 29
```

变更 3 个：`README.md`、`tools/tools.json`、`.github/workflows/deploy.yml`。

若按原逻辑推送，会白白重传 44 个文件、产生 47 次 commit。**已改为单 commit 提交**
（走 Git Data API：建 blob → 建 tree → 建 commit → 移动 ref），本轮 32 处实际改动只触发 **1 次 CI**。

### 6.2 线上验收脚本长期落后于本地

项目里同时存在 `_trash_e2e.cjs` 与 `_trash_e2e_live.cjs` 两份（版式同理），本地那份已更新到
「40 篇 / 10 工具」，线上那份还停在「20 篇 / 2 工具」——**直接跑会把线上全绿误判成大面积失败**。

**已合并为一份**，用环境变量切换：

```bash
BASE=http://127.0.0.1:8899 node _trash_e2e.cjs     # 本地（默认）
BASE=https://xiaoguaiguai.cn node _trash_e2e.cjs   # 线上
```

两个 `_live` 副本已删除。**两份必然漂移**，这是本轮最该记的一条教训。

## 九、下一步建议

1. **内容纵深**：现有 40 篇已覆盖高频场景，建议下一轮转向**系列化**——把「婴幼儿养育」的睡眠/辅食/出牙/生病串成一条时间线，让访客能连续读，停留时长和站内跳转会明显好于零散单篇。
2. **工具与文章互链**：如「专注计时器」↔ `jiaoyu-screen-time-rules`、「句式转换器」↔ `qinmi-facts-vs-feelings`。工具解决「现在怎么做」，文章解决「为什么」，互链能同时提升两者的价值感。
3. **配图策略**：列表页现为纯文字索引（上轮决定），首页仅保留 1 张焦点图。若后续 AdSense 对内容页密度有额外要求，优先给**文章详情页顶部**补图，而不是回退到列表大图。
4. **数据看板**：工具全部本地存储、无上报，因此拿不到使用数据。若您想看「哪个工具真被用」，需要单独设计一个**匿名计数**方案（只报事件、不报内容），这属于新增能力，需要您先确认是否要做。
