## 七之二、2026-10-23 增补：OAuth 接入与外链复核

### OAuth 接入（发现并修掉一个致命协议错误）

要求文档提供的 OAuth Worker 代码是「callback 换完 token 后 `302` 回 `/admin?access_token=...`」，
但**Sveltia CMS 根本不读 URL query 里的 token** —— 照此实现登录会「点了没反应」且不报错。

读 `sveltia-cms.mjs` 源码 + 对齐官方 `sveltia/sveltia-cms-auth` 后确认真实协议是 **popup + postMessage**：

```
CMS 开 popup → /oauth/authorize?provider=github&site_id=<hostname>&scope=repo,user
  → Worker 校验 site_id 白名单 → 下发 csrf-token=<provider>_<32hex> Cookie → 302 GitHub
  → 回 /oauth/callback?code=&state= → 校验 state === Cookie.csrfToken → 换 token
  → 返回 HTML，页内 postMessage('authorizing:github')
  → 收到 opener 回信后发 authorization:github:success:{"provider":"github","token":"…"}
```

> 源码里另有 PKCE（`code_challenge`/`code_verifier`）与 hash 路由 `/signin/<base64>`，
> 但那两条**只走 GitLab / Gitea**；GitHub 的 `auth_type` 是 `const: ''`，永远走上面这套 netlify 式代理流。

**已重写并部署**（`oauth-proxy/src/index.js`），验证结果：

| 检查项 | 结果 |
|---|---|
| 凭证有效性（假 code 探测） | ✅ `bad_verification_code` = ID/Secret 匹配 |
| 回调地址登记校验 | ✅ 真地址通过 / 假地址报 `redirect_uri_mismatch` |
| 302 授权跳转 | ✅ Location 带真 `client_id` + `state` |
| CSRF Cookie | ✅ `csrf-token=github_<32hex>`，`HttpOnly; SameSite=Lax; Secure` |
| 回调 popup 协议 | ✅ 握手 + 回信 + Cookie 清理 8/8 项 |
| CSRF 防护 | ✅ state 不匹配 → `CSRF_DETECTED` 拦截 |
| 无 Cookie 分支（新增） | ✅ → `CSRF_DETECTED` + 可操作提示（原误报 `UNSUPPORTED_BACKEND`） |
| 域名白名单 | ✅ `evil.com` → `UNSUPPORTED_DOMAIN` 拦截 |
| 前端真实点击 | ✅ 无头浏览器点登录，弹窗成功抵达 GitHub 授权页 |
| 登录链路回归（修复后） | ✅ 弹窗 URL = `github.com/login?client_id=Ov23liLf4RUqo9Koviil&return_to=…%2Flogin%2Foauth%2Fauthorize%3Fclient_id%3D…%26scope%3Drepo%252Cuser%26state%3D…`，client_id/scope/state 齐全 |
